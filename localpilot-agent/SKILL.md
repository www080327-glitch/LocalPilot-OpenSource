---
name: localpilot-agent
description: Delegate workspace file inspection, coding and bounded long tasks to a configured LocalPilot Agent service; retrieve authoritative progress and receipts through its HTTP or MCP adapter.
---

Use LocalPilot when the user wants execution in its configured workspace, persistent progress, tool receipts, or a task that should survive the calling client's disconnect. Handle simple conversational replies locally when delegation adds no value. The host controls models, workspace, tools and permissions.

The calling host needs `LOCALPILOT_URL` and its own `LOCALPILOT_TOKEN` in the adapter environment. Never ask the model to find tokens or copy provider credentials. First call `localpilot_capabilities` to verify authenticated identity, route tool ceilings, workspace, cloud scope and API version. Prefer the configured MCP tools. If MCP is unavailable, invoke `scripts/localpilot_adapter.py` relative to this skill with the same tool name and JSON arguments. It uses Python 3.10+ and the standard library.

1. Generate one stable idempotency key for the intended operation and persist it before submission. Call `localpilot_submit` with `input`, `idempotency_key`, optional `session_id`, `model`, `timeout_seconds`, `max_output_tokens`, `origin_agent`, and `parent_task_id`. The server binds ownership to the authenticated client; provenance strings grant no authority. If capabilities returns a human-authorized session, submit explicitly into its ID after checking effective_scope. Save the returned task ID and session ID immediately. Do not register or execute the server's returned tool calls in the calling host.
2. Call `localpilot_status` to inspect `status`, `quiescent`, `required_action`, `error`, `recovery`, `tools`, `receipt_summary`, `verification_summary` and `result`. Use `localpilot_events` with the saved cursor for bounded actual SSE progress, and `localpilot_result` for the complete final snapshot. Poll at a modest interval; the HTTP SDK also supports `/localpilot/v1/tasks/{id}/events` and Last-Event-ID for progress. A disconnected stream leaves the task running.
3. For `requires_approval`, return the exact action preview and current action ID to the authorized operator. The calling Agent's ordinary token cannot approve. For `requires_human`, return takeover/recovery information to that operator. `localpilot_continue` accepts the current ticket only for an operator-authorized SAFE_TO_RESUME checkpoint; it cannot self-authorize an approval or clear UNKNOWN. After the operator acts, query the same task ID.
4. Report the final result only after examining independent Runtime, delivery, verification and engineering states. `completed` is a Runtime state; `engineering_status=unverified` is not a semantic acceptance certificate. `requires_approval`, `requires_human`, `failed`, `incomplete`, `cancelled`, `timed_out` and UNKNOWN remain explicit. Include task ID, verified outputs, limitations, and relevant receipts.
5. Continue a conversation by submitting only the new turn with the existing session ID and a new idempotency key. Resolve the current active task first. Closed/cancelled sessions require a new session.

Use `localpilot_cancel` for explicit cancellation. Poll until quiescent and inspect receipts: an already dispatched mutation may have happened. Cancellation cannot certify rollback.

On a submit timeout or lost response, retry the identical request with the original key. Changed input/session/model under that key receives 409. An accepted key returns the same task even after restart, failure or UNKNOWN; it never launches a second execution. If the key is lost, ask the operator to reconcile records before resubmitting a task with side effects. HTTP errors and EOF never imply success. Recover an expired SSE cursor by retrieving the task snapshot, never by creating a replacement task.

Do not delegate LocalPilot back into this Skill, run another calling Harness from LocalPilot, or request recursive service delegation. The service package has no external-delegation tool and host command execution is off by default. If the task is already a LocalPilot delegation, handle the returned result in the calling host instead of creating another delegation.

For host installation, read [references/installation.md](references/installation.md). Service startup is in the separate service distribution's `SERVICE_DEPLOYMENT.md`. This skill supplies invocation guidance; all permission decisions, egress checks, action ticket validation, receipt reconciliation and UNKNOWN quarantine are enforced by the server.

If this host denies an MCP or HTTP tool call, report **Host Denied** and stop that attempted call. Do not switch transports, shells or identities to evade the refusal. Do not delegate credential discovery, authorization changes, unselected directories, unrestricted shell execution or tasks outside advertised capabilities. Only a separately authorized human operator can approve high-risk actions. For UNKNOWN, preserve task/session/key and inspect receipts; do not resubmit, continue, auto-recover or replay effects.
