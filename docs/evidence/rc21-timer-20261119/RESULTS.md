# RC21 停服定时器修复验收（2026-11-19）

**NOT_RELEASE_READY，尚未完成所有要求。** Core 全量仍有一个插件类初始化错误，使24项用例未执行；真实桌面、动画和新手观察也未全部验收。本候选修复了正常停服后已经开始的超时回调仍改变任务状态、尝试写入已关闭存储的问题。这个缺陷来自真实失败日志，使用真实 Timer、TaskService 和 SQLite 复现后做最小修复；没有增加预算或吞掉存储异常。RC20 的全部失败和原包继续保留。

## 本轮变化

创建任务与恢复任务的定时器使用同一个私有入口。在原服务锁内读取关闭状态：服务打开时执行原有超时取消；服务关闭后不再进入取消。公开 `cancel()` 和 `shutdown()` 方法未改变，正常超时、审批、取消与未知结果语义保留。

新增回归在原代码上失败，捕获同一个后台线程 `PersistenceError`；修复后与四项已有超时/恢复检查一起 5/5 通过。同一个实际 SQLite 复现脚本显示：原版内存变为 `cancelling`、数据库仍为 `requires_approval`；新版两者都保留 `requires_approval`，内存快照、持久检查点和 journal 不变，写工具未派发。新增回归另外核对了整个数据库文件字节不变。独立复审核对了创建和恢复两个入口、已有可重入锁和显式停服取消路径。

此前 HTTP 测试夹具在初始化失败时不会调用 tearDown，已改为资源建立后立即登记清理；真实初始化失败验证服务器线程、socket、临时目录均释放，原模块4/4通过。其预算、测试数量和业务断言不变。这能修正确定的资源泄漏，但不能证明它是此前两项插件错误的原因。
