# RC17：逐条任务存储与 Super Agent 分工

2026-11-17，接续 PR #15 的 RC16 提交 `c411dd1f92ad09e3b6e095acc96bc65c12107d5e`。当前源码版本为 Desktop **5.0.1-rc.17**、Core **5.0.0b34**、Companion **0.5.7b11**、Suite **0.2.0b34**；Channels 保持 **0.1.0a4**。本次改动不构成新的正式 Release，也不重复计入此前四类各十项审计。

## 用户可见的分工

在现有“添加本机模型与协作 Agent”入口中，选择主模型、勾选伙伴后，可以再指定“探索模型（只读）”和“审阅模型（只读）”。同一伙伴可以兼任两个职责；取消勾选或改选主模型会同步清理不再有效的职责选择。保存仍创建新的合作路由，保留旧路由和已存在的会话。

Super Agent 继续决定任务、分派工作、收集收据并完成交付。小范围路径定位可直接使用工具，较大的独立搜索可以交给探索子 Agent；方案疑点、失败分析或关键 diff 可以按需交给审阅子 Agent。没有强制每次 grep 都调用模型，也没有固定“第二次失败必调顾问”或自动付费模型升级。

两个命名职责均由现有 Gateway 限定只读，不能修改文件或执行 shell。需要运行测试时，由已有权限的父 Agent 或普通执行子 Agent 执行，并保留对应执行者的真实收据。审阅者的文字不替代测试验收。本次没有实现 worktree 审计，子任务仍使用受限的同一工作区。

原五档本地／云端来源策略继续生效。职责不会建立第二个路由器：全云配置保留所选主 backend，混合本地／云端时仍遵循原来源策略。命名角色子任务限定在自己的配置 backend 内，不能自行切换模型。普通 `delegate` 的既有行为不变。真实 Desktop Full 注册的 Shell 也按子任务有效能力过滤；固定角色子任务的自适应模型锁绑定该角色，父级锁保持原值。

## 配置与实现

角色复用现有注册 route，示例中的名称必须已存在且同属一个工作区：

```json
{
  "cooperation": {
    "routes": ["search-model-route", "review-model-route"],
    "optimizer": {"mode": "cloud-only"},
    "roles": {
      "search": "search-model-route",
      "review": "review-model-route"
    }
  }
}
```

`roles` 可省略。Suite 只在设置非空角色时要求 Core 声明 `worker_roles_v1`，避免把旧 Core 不认识的配置写入后造成重启失败；原无角色合作配置继续使用已有能力约定。这是配置兼容检查，没有新增任务权限审批。

Core 将注册路由转换为已有 Hybrid alias，向主模型提供可用角色、模型、思考强度和只读属性。`delegate` 仍要求 `backend_preference`，可使用 `role` 选择命名职责。冲突的 backend、模型、tier 或写权限在既有提案校验入口返回具体错误；其余预算、异步调度、取消、批准和收据流程不变。

伙伴 route 显式配置的 `thinking` 优先于父 Agent 的思考强度。未显式配置的普通伙伴仍按原规则继承父级兼容值。由此可使用主 Luna high、审阅 Sol medium，而不会因为 Sol 也支持 high 就把 medium 悄悄覆盖。角色和模型身份参与持久化配置指纹，恢复沿用相同的子任务构造流程；无角色配置不追加新指纹字段。

## R8 失败的归因与修复

RC16 的 R8 原记录仍保留为整体工程 FAIL。外部代码测试通过，但 Parser 子任务没有自己的成功测试收据，不能由父任务补测替代。

新审阅确认两类问题需要区分：

1. 父模型改写有效解释器路径，导致子任务先收到退出码 127；Parser 子任务没有完成后续自验收。这是当轮的委派和恢复行为问题。工具任务合同现在明确要求保留提供的解释器和检查命令，检查不能启动时依据实际环境重新规划，并报告未运行的检查。它没有硬编码此验收夹具或放宽通过条件。
2. `delegate` 在没有注册相应 worker 的 Hybrid 配置中仍广告 `LIGHT/STRONG`，导致模型使用已广告的 LIGHT 后收到未注册 backend 错误。这是产品声明与可用后端不一致，已改为只广告实际注册且符合来源策略的 tier；移除了过时的 DeepSeek 默认描述。

RC16 报告中“没有 Runtime Shell 故障证据”仍适用于当时解释器路径错误；不能据此把所有 delegate 错误也归为模型能力。本次以确定性的实际实现测试复现并修复 tier 声明和伙伴思考强度问题。

普通旧 V5 会话的固定 system prompt 保持原文，避免升级后触发稳定指令不一致。通用委派指引放在工具说明和有工具时的动态 Host state 中；无工具的纯文字请求不追加这段指导，避免无关文本挤占小窗口。新增角色提示只用于明确配置了角色的新会话。

工程验收脚本新增 `--model` 和 `--reasoning`，默认仍为 `gpt-6-luna` / `medium`。主与子任务实际推理配置单独记录；prompt 模板、原始夹具、验收函数和预算保持不变。解释器绝对路径由运行环境生成，不能把不同环境的 prompt 字节称为完全相同。原 RC16 + Luna high 与修复候选 + Luna high 分开运行、分开归档，不把模型强度变化与产品修复混为一个结论。

## Companion 逐条任务存储

原先每次任务状态、provider 查询或分页都读取 `state.localpilot_tasks` 的完整 JSON 映射。本次在同一个 SQLite 数据库中增加逐任务表：每个 task ID 一行，完整原 record 作为 payload 保留，单独索引时间、session、endpoint 和可恢复状态。

首次打开含旧映射的数据库时：

1. 校验旧映射入口，保留全部字段和任务身份。
2. 通过 SQLite backup 生成权限为 0600 的任务迁移前备份。
3. 在同一事务创建新表和索引、导入任务、删除旧映射键。
4. 后续启动使用逐条存储，不重新解析和导入旧映射。

新增任务或状态更新只写对应行。默认 30 条、最多 50 条的任务分页使用 `(timestamp, task_id)` 索引游标，旧任务可按原 ID 查询。恢复已接受提交使用 `put_if_absent`，不覆盖已保存的更完整结果。provider、subject、授权 scope、原请求、事件游标和其他未知历史字段均保留。

同 session 的上下文权限判断仍逐条检查所有相关旧请求，查询先按索引排除无关任务，再流式读取。没有新增权限缓存，也没有为了提速跳过原来的撤销和来源校验。启动恢复按既有监视数量上限读取可恢复任务。

显式“清空记忆”同时清除任务行和自动任务迁移备份，重开不会从备份复活任务。普通保留策略不删除这些任务记录。

### 降级与存储边界

旧 Companion 没有新 schema 的主动拒绝机制：直接用旧版打开升级数据库会读不到旧 JSON 键。降级需要停止服务，恢复迁移前备份；备份之后的新任务不在旧快照中。不能把 Core schema 3 的拒绝行为套用到 Companion。

该备份在任务行迁移前创建；MemoryStore 原有初始化可能已经运行，不主张整个数据库升级前没有任何写入。备份会额外占用磁盘。分页总数仍执行 SQLite `count(*)`，同一长会话的上下文复查仍随该会话历史增长；按条读取解决的是每次操作都解析和重写全库任务 JSON 的问题，不代表所有操作恒定时间或历史不占空间。

## 验证口径

确定性回归应覆盖实际 SQLite 的迁移失败回滚、原 ID/归属、同时间戳翻页、旧版本备份恢复及清空；实际 HTTP 适配器测试应覆盖角色模型与思考强度、只读工具、父模型继续统筹和 SQLite 重启后的身份。脚本化 HTTP 结果不冒充外部模型能力评测。

历史性能对照使用同一脚本和解释器、相同合成数据结构，先跑 RC16 再跑候选。精确查询真实旧任务、状态更新、首页、后页和上下文检查分别记录；首次迁移与稳态测量分开，SQL 追踪和内存采样不混进计时样本。每个规模只有一个实际脚本化任务，其余为明确标注的合成历史。

真实模型工程验收沿用原独立子任务测试门禁；所有失败、跳过和环境阻断保留。单次通过不代表总体成功率，模型费用也不能仅凭 token 缓存比例推算。

## 参考边界

[Anthropic advisor 官方说明](https://code.claude.com/docs/en/advisor)支持主模型咨询顾问，但具体时机由模型决定；顾问读取完整对话，其自身读取不缓存。[子代理官方说明](https://code.claude.com/docs/en/sub-agents)支持独立上下文、模型和工具范围，也支持 worktree；它不是当前 LocalPilot 只读角色已具备的隔离执行能力。

本次没有引入来源未明确的 JEV 服务。LocalPilot 已有纯代码规则处理来源、预算、停滞、失败和队列等确定性分支，模型负责需要语义判断的任务分解和审阅。
