# RC17 续作：截断恢复与会话依赖查询

本轮基于 PR #15 的 `6c923a95c749d1db2c6d2548e2109cd79b02d938`，沿用 Super Agent 主控和既有合作路由。变更组件为 Core **5.0.0b35**、Companion **0.5.7b12**；Desktop **5.0.1-rc.17**、Suite **0.2.0b34**、Channels **0.1.0a4** 保持各自版本。旧 RC17 结果和失败证据保持原样。

## 子任务输出截断

R10 的 Parser 子任务用尽单次 4096 输出 token，响应中的工具提案没有执行，随后父任务试图创建第三个子任务，被原有两子任务预算拒绝。

V5 子任务现在在第一次 `finish_reason=length` 后保留已经完成的收据和全部调用用量，丢弃该次响应的工具提案、半截文本与 native replay。在同一子任务内追加宿主反馈，请模型拆分成较短的完整调用与补丁后继续。它不更换模型，不增加输出、总 token、step、工具调用或子任务数量预算；下次请求仍经过原有准入、权限和取消检查。

只有还存在执行步时才安排这一次恢复。第二次截断继续停止；最终交付保留步不挪用作新执行步。`WorkerOutputRecovery` 事件及 ready checkpoint 留下实际恢复记录，恢复次数由已持久化的用量记录判断，重启不会重新获得次数。父任务既有 finalization 和验证等级保持原语义。

## 同一会话的历史来源检查

上一版已消除整份任务 JSON 映射的读写，但 `session_context_current()` 仍逐条解码同会话所有任务的完整 payload。现在每条任务附带从原 request 派生的 `context_request`，只保留已有有效性检查所需的 memory ID、文件路径和 observation ID/source reference；规范化后可合并重复依赖集合。

查询通过 `(session_id, endpoint, timestamp, context_request)` 覆盖索引读取不同依赖集合，再逐一调用原来的 `context_current()`。完整 payload、任务 ID、未知字段和收据不删除。权限撤销、memory 删除、文件变化和观察来源有效性仍实时复查；没有缓存授权结论。

这是减少 payload 解码、返回数据量和重复检查，不是任意长度会话的常数成本保证。SQLite 仍扫描匹配的索引项，不同依赖集合仍各需实时检查。分页 `count(*)` 的语义不变。

## 迁移和旧版本写入

旧逐行表在同一事务添加可回填列和索引，并从完整 payload 生成投影。更早的完整 JSON 映射仍沿用已有私有备份和事务迁移。缺失 request 用 JSON `null` 表示，检查仍拒绝返回依赖无法重建的内容；SQL NULL 仅表示待回填的派生列。

旧 b11 writer 不认识新列。新插入行留下 SQL NULL；旧式 upsert 修改 payload 而未同步投影时，SQLite 触发器将该行投影置为 SQL NULL。新版按部分索引回填这些行，避免降级写入后使用过期依赖。当前新版写入在同一事务补齐投影，只写一次完整 payload。派生索引更新不是任务的第二次完整写入。

新增列、索引及触发器不阻止 b11 读取原 payload；更早 JSON 版本的降级仍必须停止服务并恢复它的迁移前备份。备份之后新增的任务不在旧快照中。新的迁移和重开验证不替代原生安装/升级验收。
