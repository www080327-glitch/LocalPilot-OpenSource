# RC19 续作：可恢复的配置、角色基础动作和原文检索

当前组合：Desktop `5.0.1-rc.19`、Core `5.0.0b36`、Suite `0.2.0b35`、Companion `0.5.7b12`、Channels `0.1.0a4`。基线是 PR #15 的 `fe9765c69ce8a39e8a3682d61ceb67c86894c3b4`。本轮保持 **NOT_RELEASE_READY**；验收结果、受测源码和运行材料见[RESULTS](../evidence/rc19-usability-20261119/RESULTS.md)。

## 第一次使用和失败后重试

云端连接原来对同一提供商与模型直接返回 `already_configured`。界面虽然保存了新密钥文件，服务仍引用旧文件。现在界面明确说明再次保存会更新这个模型的密钥，并使用 Suite 的显式 `--replace-key` 路径：替换选中后端及共用旧密钥的同模型后端，清除会盖过文件的旧 `api_key_env`，保留会话、路由权限、其他模型和 Companion 当前选择。旧密钥文件保留，恢复服务失败时还原原配置。CLI 未加该选项时继续保持原来的幂等行为。此操作保存并重新连接本机服务，不声称已经向提供商验证 API 密钥。

首次设置仅在 **macOS arm64** 使用 MLX 路径。Intel 和 Linux 使用已有的本地 HTTP 连接入口；ARM Linux 不再被误判。两个跳过下载按钮实际进入下一步；完成页若尚无可用模型，会显示“还需连接模型”和返回按钮。发现服务只有一个模型时预选它；地址改变会清空旧模型和上下文预算，避免把一个服务的能力套到另一个服务。

升级计划显示当前实际阻挡安装的进程，并在页面提供停止 Core 和 Companion 的按钮。Core 返回 `stopping` 时保持可重试，不显示“已停止”。新建计划按新计划 ID 读取收据，不再带入上一份计划的成功或失败。应用归档清理在验证恢复后的代码签名失败时停止，原 APP 不会进入废纸篓。构建检查默认读取准备资源时产生并经清单验证的架构锁，避免错误地使用另一架构的仓库锁。

保存云端配置后立即刷新主界面模型列表。任务详情按真实 Core 的 `done` 状态计算已完成目标，同时兼容原有 `completed` 数据，并显示中文状态。

## 同一个角色先恢复可见基础动作

桌宠设置提供“选择角色文件夹”：选择含 `pet.json` 和 `spritesheet.webp` 的原角色 v2 包即可，不要求手动放进隐藏目录。读取原包的注册角色 ID 和显示名，沿用图集解码、透明区域与尺寸检查。

新增的“使用基础动作”是用户明确选择的模式。它用当前角色原有的 8 列、11 行图集呈现待机和方向动作，不把另一个角色或新画作替换进来。没有额外探头姿态时也可以显示与移动。原六锚点专用探头、尾巴和其他额外图片仍使用原姿态包；基础模式不表示这些美术要求已经完成。

新开关单独写入 `pet-appearance-v1.json`，原 `pet-settings-v1.json` 保持 RC18 可读取的格式。这样回到 RC18 时不会因未知字段使全部偏好恢复默认。诊断继续保留 `character` 字段，按已导入角色识别身份，并增加 `appearance_mode`。

Mac 拖动按相邻事件的位移计算方向，中途反向不再等到跨过最初按下点才变更。Linux 拖动观察真实鼠标按钮状态和窗口位移，释放后结束；不靠固定延时猜测释放。实际 GDK X11 后端才能提供本实现使用的全局坐标；Wayland 下明确报告位置不可用并保留原锚点，不把 Tao 返回的缓存零坐标当作实际位置。

## 动画报告的含义

页面采样排除尚未载入的图片、透明祖先和裁剪区域外的精灵。频率按完整阶段持续时间计算，停顿不会从分母中消失。报告明确标记 `visible_element_styles` 和 `pixel_visibility_verified=false`；没有动态阶段为 `NO_ANIMATION_STAGES`，不能写成 0 Hz 或通过。实际可见像素、物理拖动、多个显示器仍需要真实窗口录屏与操作。

## Core 同会话原文检索

SQLite 支持的 V5 会话新增 `recall_history`。模型先按短关键词搜索同一会话的可见用户/助手文字，再按稳定引用和偏移读取原文，每次正文最多 4,000 字符，搜索最多 10 条。中文、表情等结果还按现有工具的 UTF-8 字节上限缩短摘录，保留引用和准确的下一段偏移。原始归档段与任务收据保留。派生文字索引不会把全部历史 JSON 装入模型上下文。

该入口不搜索系统指令、隐藏思考、原生重放材料或任意工具原文。当前配置身份和现有工作区授权继续约束读取；历史内容不是当前文件观察或新授权。普通云端 Hybrid 按既有出站规则仅返回可披露的历史用户文字；已准入的 Desktop 上下文走其现有规则。权限/配置切换后重新挂接入口，先筛选可返回的条目再应用数量上限。

索引表是可重建的附加表，数据库继续使用 **schema 3**。RC18 可以打开同一数据库并继续写入；新版会为旧版本新写入的归档按需补索引。本轮有实际旧 Core 往返读写验证，不靠修改 schema 数字或恢复旧备份实现兼容。更早 schema 2 的原升级/降级限制仍见[RC16 文档](PERSISTENT_SESSION_SEGMENTS_20261117.md)。

执行段轮换扩展到 Adaptive、精确云端授权和已静止的 Computer 会话：保留当前轮的路由决定和用量预留，精确云授权集合不扩大，Computer 观察与恢复屏障保留。等待批准、未知副作用、未完成原生意图或活动子任务仍阻止轮换。显式较新 OpenAI worker 模型改走已有 Responses 后端；默认 Luna 与原权限/预算逻辑保持。

## 仍有边界

单个持续运行的超长任务，当前检查点仍整体序列化其活动 Runtime；任务之间分段和逐条历史查询不能消除这一成本。完整块式持久化涉及持久格式、恢复和降级导出，是单独的源码工作，见[后续任务](WORK_RC19_ACCEPTANCE.md)。

此前 Luna R10 的输出截断是真实失败；原预算内的同一 child 恢复已在 RC17 实现。R11 Sol 工程、R12 Luna medium 工程和安装态两小时运行各保留原版本结果。本轮本地协议和回归测试不替代新的真实模型稳定性统计。

整个仓库仍有需要目标机器、数据或正式研究才能完成的验收。逐项状态见[需求核对](REQUIREMENTS_AUDIT_20261119.md)，不得由本轮修复数量推断“无 bug”或所有人无需学习即可完成全部高级操作。
