## `unexpected_tool_set` 修复

旧私有启动器要求任务只有一条 `apply_patch` 收据，错误拒绝了两次只读预检。
同一校验流程还错误使用成功收据的 `applied` 字段、固定收据总数为 1、
并把第一条预检收据当成写入收据去关联审计。官方成功字段实际为 `changes`；
`applied` 属于错误或部分执行结果。

仓库内 [校验器](../../scripts/wechat_approval_final.py) 只包含只读证据校验函数，
未复制私有启动器、服务控制、模型凭据、端口或本机绝对路径。
`validate_case(..., workspace=..., client_subject=...)` 必须显式接收宿主工作区和预期普通身份；
调用方负责取得经过认证的任务快照、事件和发送回执，本模块不发 HTTP 请求或读取登录状态。
`validate_persisted_audit(case, task, linked)` 按实际 `apply_patch` 收据关联持久审计。

修复只容许成功且非缓存的 `file_info`、`list_directory` 预检，仍要求恰好一条
`apply_patch` 收据。额外写入、未知工具、重复或复用收据、失败或 UNKNOWN、错误任务/会话、
错误审批对象、非预期路径、覆盖已有文件、摘要不符以及缺失手机发送回执均不能通过。
校验时目标必须为普通文件且路径无符号链接；POSIX 下保留文件所有者及私有权限检查。
Windows 的目录 ACL 仍由宿主管理，本工具不修改 ACL。

## 可复现专项测试

在仓库根目录执行；不需要凭据、服务、登录状态或原始真实证据。
测试只使用合成身份、合成收据和临时文件，校验逻辑没有网络或服务启动入口。

Windows：

```powershell
python -B -m unittest tests.test_wechat_approval_audit -v
```

WSL2 Ubuntu，在同一检出的仓库根目录：

```sh
python3 -B -m unittest tests.test_wechat_approval_audit -v
```

本次入库预检结果：Windows 13 通过，WSL2 Ubuntu 13 通过；各 0 失败、0 跳过。
修复前已复现 `unexpected_tool_set` 和后续 `write_receipt_path_mismatch`。
此前安全切换与验收辅助测试为 Python 22、Node 8 通过，属于历史结果，本次未重跑。

此前已用修复后的函数只读重放保存的两条真实任务证据，两条均通过，所读证据文件摘要未变。
这是保存证据的离线自动校验通过，不是重新进行宿主鉴权查询，也不是重新发送手机任务。
运行中的旧启动器不会自动加载磁盘修改；本文不声称其现场 `verify` 已返回成功。
无需重新采集真实工具执行即可检验此次修复。
