### 1. 构建、安装和保留数据的回滚

在真实 M1 Max 上按现有资源准备和 `desktop/scripts/build-macos.sh` 构建 RC19 Test APP。四组件 wheel 必须来自当前受测源码。使用 `src-tauri/tauri.test.conf.json` 与独立 `LP_INSTALL_TEST_ROOT`，通过 `scripts/install-local-app.py` 的现有计划/执行/收据流程完成 RC18→RC19→RC18→RC19。先读脚本 `--help`，不猜参数。

检查 Test 身份、签名、架构、安装后实际 Python 模块来源、四组件版本、目录散列。生成计划后，用界面停止 Core 和 Companion；有活动任务或 UNKNOWN 时先核对原结果。RC19 的 Core 附加检索表保持 schema 3，必须验证回到 RC18 后可读写，再升级仍有全部任务 ID/原文/收据；不要靠恢复较早备份丢弃新记录来制造通过。更旧 schema 2 的限制另按原迁移文档处理。

### 2. 普通人首次使用和错误恢复

运行仓库现有全部 Playwright 用例并保留逐项 reporter 结果、失败截图和 trace；当前页面断言未通过的项优先。使用锁定依赖；需要系统 Chromium 时沿用已有 `LP_UI_CHROMIUM_EXECUTABLE`，不关闭 sandbox。

从空白测试数据开始实际完成：选择文件夹、连接模型、发送第一个文件任务、查看结果、取消与重新查询。验证以下新行为：

- 跳过模型下载会进入下一步；无模型时完成页明确提示并能返回连接。
- 一个本地模型自动预选；修改地址后旧模型与上下文预算被清空。
- 填错密钥后保存更正值，实际后端引用更新；原会话和其他模型不变。密钥不录屏、不进日志。
- 保存新提供商后模型列表立即更新；任务面板的 `done` 显示已完成。
- 从旧成功升级记录创建新计划，不显示旧成功/错误收据，按钮对应新计划。
- 服务返回仍在停止时页面可继续检查；失败后保留草稿和原任务，不自动重复未知副作用。

“小学生都会用”不能用开发者自评替代。先用无终端的常用任务路线逐步操作，记录每次不得不查文档、找隐藏路径、解释术语或借助命令的地方；修复可复现死路。真实用户测试需要实际参与者，不能虚构观察结果。

### 3. 桌宠素材、动画和物理拖动

个人素材交付 `LocalPilot-RC19-Personal-Pet-Atlases.zip` 含 8 套原始公开图集，图像与元数据字节未改；原作者 fywdy，固定上游提交 `d5bbb27c79e5c08e8b8ab44d4023cd35a67418e2`。图像 CC BY-NC 4.0、JSON MIT，保留署名和 NOTICE，仅用于本次个人非商业导入，不打进产品发行包。

解压后在桌宠设置点“选择角色文件夹”，选择与原角色同名、含 `pet.json`/`spritesheet.webp` 的目录，勾选“使用基础动作”。检查角色实际可见、身份正确、重启保留、缩放正确。这个模式不需要丢失的私人额外姿态包。

实际鼠标按住角色，分别向左/右/上/下拖动，中途反向、停住再继续，释放后观察收边；六个锚点都检查，保留有时间信息的录屏和原生诊断。多个显示器必须有实际第二台显示器，覆盖负坐标和不同缩放，不能用单屏窗口位置冒充跨屏。

主动触发 `RETRACTING`/`PEEKING`，用既有 `measure_animation` 入口采样并录制可见窗口。阶段完整分母下可见变化至少 24 Hz；回调次数、CSS 报告和截图不能单独证明实际显示帧率。没有阶段记 `NO_ANIMATION_STAGES`，不可见记未通过可见性，不能写成有效 0 Hz 测量。减少动态效果保持原状态并单独检查其预期静态行为。

若还需完成原高级探头、尾巴/水花与特定角色情节，恢复本机原 `pack.json`、`poses.png` 及其列明补充图片后验收。只搜索用户已授权的素材路径；找不到则记录具体缺失，不改角色、不伪造姿态，不上传私人画作。

优先执行以下尚未完成的源码工作：

1. **单个超长活动任务的增量持久化。** 按 `RC19_RUNTIME_FOLLOWUP.md` 重跑真实 TaskService+SQLite 的 96 次文件读取负载，确认成本随活动记录增长。设计同一 RuntimeStore 内的块/引用格式，使稳定消息、完成收据和子任务状态无需在每个边界整体复制与重写；不得只减少模型请求 token 或隐藏历史。必须同时处理事务中断、校验失败、幂等、UNKNOWN、不重放，以及 Suite 降级前的完整旧格式物化。向未修改 RC18 回退、继续写入、再升级必须保留回退前后的记录。达到可测的写入/序列化改善才记完成，不能保留每次完整兼容副本却宣称成本已消除。

无法访问实际设备的项继续保留未执行；可完成的源码、定向验证、证据整理和 PR 交付继续完成。当前结论仍是 NOT_RELEASE_READY，除非所有必需门禁都有对应版本的独立证据。
