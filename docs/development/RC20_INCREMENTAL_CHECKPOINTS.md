# RC20：长活动任务的增量保存

Companion 一万条历史任务的按条查询与分页已在 RC17 交付，RC19 继续验证；Core 在同一个长任务中仍会反复复制和保存完整活动记录。RC20 针对这条真实路径改造，不减少原始消息、工具收据或任务预算。候选版本为 Desktop `5.0.1-rc.20`、Core `5.0.0b37`、Suite `0.2.0b36`；Companion 与 Channels 的代码版本不变。

最终结果与受测源码见[本轮验收](../evidence/rc20-incremental-20261119/RESULTS.md)。RC19 的原始回归、失败和对照保留在[上一阶段报告](../evidence/rc19-usability-20261119/RESULTS.md)。

## 正常使用的变化

长任务每完成一步，已经保存的原文和收据不再整体序列化、重写；只保存新增内容和变化后的状态。原始任务结果、查询接口及权限保持原有含义。父代理仍负责调度，同步和异步子任务继续使用原来的运行时。

停止 Core 时，程序会在任务和子任务静止后自动整理成旧版本可读格式。Suite 在替换 Core、桌面 APP 或回滚之前也会检查并准备兼容数据。用户不需要额外执行数据转换命令。Linux 通过系统包管理器降级时，应先从界面正常停止 Core，再更换旧包。

若当前任务仍在运行，或数据完整性检查没有通过，不能把旧版安装成功当作任务已经安全恢复。转换失败时 Suite 停止换包，保留当前程序和任务数据并返回明确错误；回退失败会保存失败收据，导出日志可供检查。前向安装在执行前的准备失败允许原计划重试。异常中断留下新格式时，旧版明确拒绝打开；先用支持该格式的候选恢复和正常停止，不能恢复较早备份来丢弃后续历史。

## 保存与恢复边界

新增内容仍进入同一个 `SQLiteRuntimeStore` 事务。消息、完成收据、调用索引及任务结果的大字段按稳定顺序保存；小清单记录块的顺序、数量和散列。结构性替换或删除只使对应后缀失效。父任务对同步子任务收据使用已有稳定内部记录，公开任务快照继续复制数据。

事务一起提交块、清单和既有 journal 边界。恢复时先验证顺序、散列和目标位置，物化原来的快照结构，再调用既有恢复逻辑。UNKNOWN、未决工具意图、取消、预算、批准和禁止自动重放的语义不变。块引用是宿主内部类型，工具返回的相似字典仍是普通内容。

活动块格式标记为 schema 4，使不认识该格式的旧版不会误读过期完整检查点。正常停服或显式准备兼容性时，逐个处理确实使用块的检查点；已经完整保存的旧检查点不重写。转换增加明确的 `legacy_materialized` journal 边界，旧 journal 行、时间和散列保留，最后在同一事务恢复 schema 3。

旧版随后可以继续写入。新版重开会读取最新完整检查点，不复用降级前的旧块。归档与内存缓存也分别处理，退出活动集合的会话不因缓存仍被长期引用。

## 成本仍然存在的位置

增量保存降低的是活动工具边界的重复复制、编码和写入。工具首次产生的内容仍需保存；任务完成时生成完整 TaskRecord、任务间归档、重启时恢复活动会话，以及正常停服时准备旧格式，都仍有与对应记录大小相关的一次成本。

这不是所有操作严格恒定时间或运行时内存有硬上限的保证，也不是永久模型缓存。性能报告分别给出活动边界、结束捕获和停服转换的观察值，不把后两项隐藏在平均值里。精确云授权列表和当前模型请求本身仍按既有实现处理。

## 验证要求

使用与 RC19 相同的 96 次真实文件读取夹具，对比实际 TaskService、SQLite 边界耗时和编码写入量；另检查长同步子任务，防止大收据又经父任务路径整体复制。保留原文和真实工具执行结果。

检查提交前后故障、缺块、损坏散列、混合旧检查点、会话退出活动缓存，以及现有恢复和截断逻辑。使用未修改 `fe9765c` 的 RC18 实际读写同一数据库，再升级核对新增和旧任务均保留。Suite 用真实安装进程核验转换先于换包，正常界面停服和同一已审阅计划仍可继续。

本次不因此关闭真实模型稳定性、Apple Silicon/Intel/Linux 原生交互、可见动画或新手观察门禁。最终报告明确区分源码测试、包内执行和实际设备结果。
