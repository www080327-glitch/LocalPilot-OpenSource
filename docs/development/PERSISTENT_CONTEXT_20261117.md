# 常驻对话与执行上下文 — 2026-11-17

本次源码候选为 Desktop **5.0.1-rc.15** / Core **5.0.0b32** / Companion **0.5.7b9**；Suite **0.2.0b32** 和 Channels **0.1.0a4** 保持独立版本。以 PR #15 的既有 RC14 审计为基础，针对长期对话追加修复，原四类各十项主清单不重复计数。

## 分开保存界面历史、模型窗口和执行凭据

一个持续可见的聊天入口不要求每次把整个历史发给模型。LocalPilot 保留三个不同用途的视图：

| 层 | 用途 | 本次处理 |
| --- | --- | --- |
| Companion 对话记录 | 用户和助手说过什么、来源和显示状态 | 沿用 SQLite / FTS；搜索全部仍保留的记录，按 ID 取原文；显示历史分页读取。 |
| Core V5 请求窗口 | 下一次模型调用实际接收的上下文 | 单独保存上次已准入的请求视图和原始记录游标，仅追加新消息；达到现有上下文预算时压缩这个活动窗口。 |
| Core 原始执行记录 | 工具、权限、任务、结果、幂等性和恢复 | 原始 messages / tool receipts / events 不因模型压缩被改写；完成的任务和已关闭会话可按需归档，按旧 ID 与幂等键读取。 |

代码入口：[V5 上下文](../../agent/context_v5.py)、[模型请求](../../agent/session_models.py)、[持久化](../../agent/persistence.py)、[任务服务](../../localpilot_api/service.py)、[Companion 对话](../../companion/runtime/dialogue.py)。现有的 Desktop 委派按 control ID 使用独立执行会话；普通 Companion 问答构造受限的单次请求。提醒和被动事件不因此获得后台模型调用或工具权限。

## Core：稳定追加与明确的压缩边界

此前 V5 每轮在请求末尾临时插入 `Current Host state`，但下一次又从原始消息重建，该主机状态随即消失。因此即使旧工具结果没有改写，第二次 Responses 请求也不再包含第一次的完整前缀。

新的 `RequestHistory` 与原始消息分开保存，内容是实际已准入请求。原始记录只提供尚未送出的增量。请求先经过既有投影、字节/上下文预算和云端出站检查，再更新持久窗口；未批准的请求不进入已发送历史。恢复后继续使用同一个窗口。切换模型、出站范围、系统提示、工具定义或需要特殊电脑观察投影时，重新建立请求视图。

只有发生真实上下文压力时，才把可选历史压到输入预算的约 75%，为下一轮留空间。原始任务、完整目标记录、修订和未解决义务仍从宿主结构化状态重建，不对上一份摘要再次概括。最新完整工具组若可在真实容量内保留，会优先保留；重复的说明文字不能把本可容纳的观察挤掉。超出保护状态自身容量时仍明确报告，不能悄悄裁掉未完成事项。

75% 是本地容量启发式，不是模型缓存有效期，也不保证下一轮一定无需再次压缩。很大的新结果或保护状态仍会使后续请求连续压缩。自定义压缩、换模、改工具或改提示会有真实前缀边界；本次不声称永久保持所有推理。

OpenAI 的 Responses 适配器保留提供方实际返回的 `input_transformations`、`prompt_cache_diagnostics` 和响应 ID，随模型调用用量及持久记录保存。未返回字段与显式空数组保持区别，缓存命中不能被当成推理保留证据。字段不会混入模型下一次输入，也不额外触发模型调用。依据：[OpenAI 前缀保留](https://developers.openai.com/api/docs/guides/preserved-reasoning)、[Responses 响应字段](https://developers.openai.com/api/reference/resources/responses/methods/create)。

## Companion：找得到旧话，也把原文交给模型

旧实现的检索可以命中远期对话，但后续只到最近 100 条中取原文，并优先选择最新内容。结果是命中了仍被丢弃。本次直接从 FTS 命中取完整记录，先满足相关命中，再补最近对话；不再通过年龄窗口判定记录存在与否。助手回答的来源依赖同样按 ID 查找，避免一条有效旧依赖被最新 10,000 条截断。

单条模型摘录仍有长度限制。匹配词出现在第 500 字之后时，选取围绕匹配的片段，并附原始长度和起止偏移；数据库原文不变。最多九条历史、最多约 3,000 个序列化字符的现有准入边界保留。历史明确标注说话人，只证明曾说过，不成为已完成工作的事实凭据，也不覆盖现在的指令。已经遗忘、过期或失去访问权限的来源继续排除。

`继续`、`接着说`、`换个说法` 和对应的有限英文短语，只关联最近一对通过校验、由 `question_id` 连接的用户提问与助手回复。找不到这组记录时不猜话题。普通回答、推理转交和主动寻求 Agent 帮助共用相同的已选历史，解决提前转交时丢上下文的问题。这不是任意多话题自动识别或任务路由器。

### 界面重开与分页

桌宠通过现有认证 `pet_service` 通道读取 `pet_history`，默认取 30 条、单页最多 50 条，使用时间戳和记录 ID 作为游标。页面按原消息 ID 合并恢复记录与实时回答，保留未发送草稿和正在流式显示的回复。加载失败时可在聊天中重试；向前翻页保留阅读位置；清理记忆后，先前仍在途的旧分页结果不能重新恢复聊天。关闭记忆时不读取聊天表。分页会在原始扫描位置前进，即使其中部分记录因为来源变化不能再显示，也不会卡在同一页。

恢复范围是实际已经持久化、仍允许展示的聊天；过去未保存的委派通知不会被重新生成。Python / SQLite 回归和 TypeScript 校验通过；新增七个浏览器用例因当前 Chromium 启动及云浏览器本机连接环境受限，尚未执行页面断言，不能记为新 UI 或 macOS 原生验收通过。

## 任务积累不再耗尽全部执行名额

旧 `max_sessions=64` / `max_tasks=512` 计算所有累计对象；重启会把它们全部恢复，所以“重启解决容量不足”的旧提示不成立。现在在达到容量时，仅把终态、已静止的任务及已经关闭的会话迁入 SQLite 归档索引，并与活动 checkpoint 更新一起提交。读取旧任务、旧 SSE 或重试旧幂等键只读取记录，不重新启动 Runtime 或重做工具调用。

仍在等待批准、执行中、控制操作中或未解决恢复边界的工作不被当成完成任务丢掉。非持久服务保留有限容量，因为它没有可用于保留历史的归档存储。64 个尚未关闭的会话仍占用 64 个名额；本次不自动替用户关闭工作会话。近期任务列表有上限，旧任务可按 ID 查询；这不等同于新增无限列表分页。

### 数据库兼容性

归档需要 Core runtime SQLite **schema 2**。schema 1 在迁移前通过 SQLite backup API 生成同目录、独立命名、权限为 0600 的 `*.schema1-backup-*.sqlite3` 备份，并核对备份完整性与旧 schema；新表和版本号在事务中更新。既有备份不被覆盖。

旧 RC14 读取 schema 2 时会拒绝打开，避免看不到归档幂等键而重复执行旧任务。**代码/安装包降级与运行数据降级是两件事**：要让旧 Core 使用已经迁移的那份数据，必须先停服务并恢复升级前的数据备份。升级后新产生的记录不在旧备份内；不得直接把 schema 版本号改回 1。原 Ubuntu RC14 apt 循环使用原版本数据，不证明这次 runtime 数据迁移后的降级已经通过原生验收。

## 不照搬固定缓存时钟或 JSONL 轮换

本项目的原始记录在 SQLite 中，主要风险来自全量 checkpoint 和累计执行对象，不能靠另建一个 JSONL 文件解决。此次活动模型窗口与归档名额有边界，但**一个仍打开的超长 Core 会话仍会保留并序列化完整原始执行记录**；没有声称已经实现无限磁盘空间或无限启动性能。Companion 也遵守已有可配置保留政策，默认对话记录限额为 10,000，已过保留期或被用户遗忘的内容不会复活。

未增加“闲置 55 分钟就付费总结”的后台任务。缓存有效期和计费取决于实际接口/设置；[Claude 官方缓存文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)说明默认 5 分钟、可选 1 小时，不能从使用 Claude 推断每次请求都拥有 1 小时缓存。[OpenAI 缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)也按模型与配置区分有效期。需要针对实际请求和价格测量，不能用一例 0.19 美元或某个 token 数作为通用保证。
